Квантово-устойчивое хранение цифровых активов: гибридный KEM X25519 + ML-KEM и спектральное предсжатие на платформе Java 25

Quantum-resistant storage of digital assets: hybrid X25519 + ML-KEM key encapsulation and spectral pre-compression on Java 25

М. В. Заславцев · науч. рук. — к. т. н., доцент А. М. Романенков

Московский авиационный институт (НИУ), кафедра 806 «Вычислительная математика и программирование», Москва

АннотацияАтака «Harvest Now, Decrypt Later» угрожает уже сегодня архивам, которые должны оставаться секретными 10 лет и более: перехваченный шифротекст будет вскрыт алгоритмом Шора на квантовом компьютере. Предложена подсистема хранения, в которой ключ данных выводится через HKDF из двух независимых секретов — X25519 и ML-KEM-768 (FIPS 203), а целостность обеспечивает композитная подпись Ed25519 ‖ ML-DSA-65 (FIPS 204). Рост PQC-артефактов компенсирует конвейер «сжатие → шифрование» с авторским спектрально-энтропийным алгоритмом FOURIER. Решение реализовано на штатных API Java 25 как криптоагильный Spring Boot Starter.

Ключевые словапостквантовая криптография, ML-KEM, ML-DSA, гибридный KEM, HKDF, HNDL, Compress-then-Encrypt, БПФ, Java 25.

1Проблема

Алгоритм Шора [1] обнуляет стойкость RSA и ECC. Для данных в состоянии покоя важна не дата появления квантового компьютера (CRQC), а модель HNDL: шифротекст, перехваченный сегодня, будет вскрыт завтра. Жизненный цикл аэрокосмических изделий и их документации — 20–50 лет, что перекрывает прогнозы появления CRQC [5]. Стандарты FIPS 203/204 утверждены NIST в 2024 г. [2, 3], но их криптоанализ молод (финалист NIST SIKE был взломан на обычном ПК), поэтому, следуя ANSSI [6], мы комбинируем классику с PQC, а не заменяем её.

2Метод

Гибридная инкапсуляция. X25519 и ML-KEM-768 выполняются независимо, их секреты смешиваются через HKDF [4]:

K = HKDF-Expand(HKDF-Extract(salt, Kcl ‖ Kpq), info)(1)

В отличие от наивного хеширования конкатенации, (1) даёт Shyb ≥ max(Scl, Spq). Подпись — композит ω = (ωEd25519, ωML-DSA), принимаемый только при валидности обеих частей.

Compress-then-Encrypt. Шифротекст AES-GCM имеет максимальную энтропию и не сжимается, поэтому сжатие выполняется до шифрования. Если выигрыша нет (архивы, зашифрованные файлы), сжатие отменяется маркером NONE в заголовке — контейнер не раздувается.

Алгоритм FOURIER. Словарные методы (LZ77) бессильны на плавных градиентах телеметрии. Блок 1024 Б переводится БПФ (radix-2) в частотную область, сохраняются 8 низших гармоник, обратное БПФ даёт предсказание x̂, а в поток пишутся невязки ri = (xi − x̂i) mod 256. Кольцевая 8-битная арифметика даёт строго обратимое восстановление xi = (x̂i + ri) mod 256 без ветвлений, а невязки с низкой энтропией дожимает ZSTD.

3Эксперимент

Замеры выполнены в демо-приложении на Spring Boot, метрики собирались в Prometheus и Grafana (20 итераций после прогрева JIT). Цена квантовой устойчивости — рост артефактов (табл. 1). Контринтуитивно, сжатие ускоряет полный крипто-цикл на 29 %: компрессия дешевле AEAD-обработки исходного объёма.

4Заключение

Создан готовый к внедрению pqc-hybrid-spring-boot-starter на штатных API Java 25 без нативных библиотек [7]. Режим (HYBRID / PQC_ONLY / CLASSICAL_ONLY), уровни ML-KEM и ML-DSA и алгоритм сжатия задаются конфигурацией без перекомпиляции — это путь к будущим отечественным стандартам. Рост артефактов компенсируется предсжатием, а подпись на решётках быстрее классической.
